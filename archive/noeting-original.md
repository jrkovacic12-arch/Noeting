# Noeting

**Notice. Note. Think. Originate from nothing.**

## 1. Core philosophy

The original question was whether apps like Deepstash or Blinkist genuinely help recover attention when they still rely on repeated consumption, feeds, summaries, advertising, and engagement mechanics.

The conclusion was that meaningful content does not automatically create meaningful attention.

A better hierarchy is:

**Original source → own notes → reflection → occasional summary → creation**

Summaries are useful for discovery or previewing. They are weaker substitutes for deep reading because they often preserve conclusions while removing reasoning, ambiguity, examples, context, and intellectual structure.

AI is already sufficient for many discovery and preview tasks, so another content app is often unnecessary.

The deeper distinction is not:

**short-form vs long-form**

but:

**sustained thought vs repeated consumption**

The central question for any system should be:

**What behavior does this repeatedly train?**

---

## 2. Attention philosophy

Not every shift of attention is bad.

While reading, an idea may trigger a connection to an existing belief, personal philosophy, work problem, observation, or original thought.

That kind of shift can be productive:

**input → recognition → internal connection → original thought → brief capture → return**

The useful distinction is:

**Externally induced attentional capture**
- recommendation feeds
- ads
- notifications
- autoplay
- algorithmic next-actions
- endless scrolling
- novelty loops

versus:

**Internally generated cognitive branching**
- a spontaneous idea
- a connection between concepts
- a disagreement
- an insight
- a question
- a new hypothesis

The goal is therefore not uninterrupted attention at all costs.

The goal is to protect sustained attention while preserving genuine thought when it appears.

A practical rule:

**Capture the thought briefly, then return. Develop it later.**

---

## 3. What the system should optimize for

Most commercial content products implicitly optimize:

**time in app ↑  
sessions ↑  
content consumed ↑  
retention ↑**

Noeting should optimize something different:

**notice → capture → reflect → connect → experiment → create → revisit → stop**

Success may mean spending very little time inside the app.

The app should help the user return to life, work, reading, observation, and creation.

The important final state is:

**Done. Leave the app.**

---

## 4. Sources are broader than books

Noeting should not be a book-note application.

Useful thought can originate from:

- books
- papers
- web articles
- web novels
- videos
- films
- conversations
- work
- mistakes
- projects
- places
- observations
- boredom
- walks
- personal experiences
- spontaneous thoughts

A book should not automatically be treated as more intellectually important than something noticed during ordinary life.

The world itself is source material.

## 5. Core conceptual objects

### Source

Where something originated.

Examples:

- book
- paper
- person
- meeting
- film
- website
- workplace
- street observation
- internal thought

### Capture

Raw material that appeared.

Examples:

- thought
- observation
- quote
- question
- problem
- contradiction
- idea

### Reflection

My interpretation of the capture.

Questions:

- What does this mean?
- Why did it matter to me?
- What do I agree with?
- What do I disagree with?
- What does this connect to?
- Did this change my model of something?

### Experiment

Something worth testing in reality.

Example:

> Meetings often jump to implementation before defining the problem.

Experiment:

> At the next meeting, ask: “What exact problem are we solving?”

### Creation

Something original produced from accumulated thought.

Examples:

- principle
- essay
- design
- software idea
- framework
- decision
- project
- argument
- story
- research direction

### Review

Revisit something later, not merely to memorize it, but to reconsider it.

---

## 6. Noeting is not Anki

Anki primarily asks:

**Can you remember this?**

Noeting should often ask:

**What do you think about this now?**

Example:

> Five months ago you wrote:  
> “Freedom is not unlimited choice. It is reducing the number of things capable of controlling your choices.”

Review:

- Still believe this?
- What changed?
- What would you add?
- What evidence supports or weakens it?
- Has experience changed the idea?

This is **spaced reflection**, not merely spaced repetition.

---

## 7. Noeting is not Obsidian

Obsidian is useful as a reference product and temporary tool.

Its strengths include:

- fast note capture
- local Markdown files
- linking
- backlinks
- search
- folders
- tags
- templates
- daily notes
- resurfacing
- web clipping
- attachments
- extensibility

But Obsidian is fundamentally a general-purpose knowledge environment.

It optimizes primitives such as:

**write → link → organize → search → visualize → extend**

Noeting should have a stronger behavioral model:

**notice → note → think → originate**

The problem with a completely general tool is that users can spend large amounts of time organizing knowledge without actually thinking, experimenting, or creating.

Noeting should make the desired cognitive behavior the default.

Use Obsidian on the phone temporarily.

Purpose:

- understand existing note-taking workflows
- observe which features are genuinely useful
- identify friction
- identify unnecessary complexity
- discover which actions should require one tap
- observe how resurfacing should work
- understand what Noeting should deliberately exclude

Do not heavily customize Obsidian.

A temporary structure is sufficient:

```text
Inbox
Thoughts
Sources
Experiments
Creations
```

Record product observations such as:

```text
This is unnecessary.
This should take one tap.
This should close immediately after saving.
I want this thought resurfaced differently.
I want to develop the thought rather than organize it.
This feature creates unnecessary maintenance.
```

Those observations become product requirements.

## 9. Product identity

# Noeting

**Notice. Note. Think. Originate from nothing.**

The name combines the act of noticing with noting and thinking.

The product should represent:

- attention sovereignty
- creative thought
- reflection
- intellectual independence
- deliberate technology use
- creation over consumption

The device should function as a tool rather than a mental habitat.

### Tool mode

> I opened this device to do X.

### Habitat mode

> I opened the device and now other systems determine what happens next.

Noeting should reinforce tool mode.

---

## 10. Core interaction

The main interaction should be extremely fast.

### Capture

```text
What appeared?

[ Thought ]
[ Observation ]
[ Question ]
[ Idea ]
[ Experiment ]

____________________

Optional source:
Book / Web / Work / Life /
Film / Person / Other

Save
```

After **Save**, the screen should close.

No recommendations.

No AI-generated response.

No related-content feed.

No congratulatory animation.

No invitation to continue consuming.

The purpose is:

**preserve thought without stealing the user's attention from the original activity.**

## 11. Main navigation

A minimal structure:

```text
NOETING

+ Capture

Today
Library
Review
Create
```

### Capture

Preserve something quickly.

### Today

A deliberately finite set of reflection prompts.

### Library

Everything previously captured.

### Review

Resurface meaningful ideas.

### Create

Develop groups of thoughts into something original.

## 14. Review

Noeting should resurface old thought intentionally.

Example:

```text
YOU WROTE — 5 MONTHS AGO

"Remote work makes me more productive."

Still true?

[ Yes ]
[ No ]
[ More complicated ]

What changed?

____________________
```

The goal is to observe the evolution of beliefs.

A note should not become sacred merely because past-self wrote it.

---

## 15. Create

Creation is a first-class function.

If several notes begin clustering around an idea:

```text
ATTENTION SOVEREIGNTY

12 thoughts
4 observations
3 experiments
2 contradictions

Possible synthesis

• intentional entry
• resistance to externally selected next-actions
• tolerance for boredom
• protection of internally generated thought
• deliberate exit
```

Possible outputs:

- write an essay
- formulate a principle
- design an experiment
- create software
- make a work decision
- develop a project
- produce nothing yet

The system should support:

**information → interpretation → synthesis → creation**

not merely:

**information → saved**

---

## 16. AI philosophy

AI should be available, but behind deliberate actions.

Good AI functions:

- find contradictions in my notes
- show related thoughts
- summarize how my thinking changed over six months
- challenge this argument
- help synthesize selected notes
- identify unresolved questions

Bad default behavior:

- automatically replying to every capture
- continuously suggesting related content
- generating more material automatically
- telling the user what to think next
- replacing personal interpretation

AI should be summoned as a tool.

It should not become another source of continuous stimulation.

---

## 17. Intention gates

Noeting may eventually help create friction before entering attention-consuming environments.

Example:

```text
What are you here for?

[ Find something specific ]
[ Continue something ]
[ Create / upload ]
[ No clear reason ]
```

If the answer is:

**No clear reason**

the system should not provide another activity to replace it.

The point is restoring conscious choice.

---

## 18. Personal queue instead of recommendation algorithms

Replace:

**algorithm → next thing**

with:

**past-self → present-self**

The queue contains only things intentionally chosen earlier.

Example:

```text
TO EXPERIENCE

Read:
The Beginning of Infinity

Watch:
Film X

Explore:
How cities affect walking behavior

Think:
Why does boredom produce ideas?
```

Nothing should automatically enter the queue.

## 19. Technical direction

Long term, Noeting should probably be a local-first application.

Core principles:

- works fully offline
- local storage is primary
- sync is optional
- user owns all data
- data can be exported
- no proprietary lock-in
- readable/open format where practical
- encryption before remote synchronization
- no mandatory account for single-device use

Potential architecture:

```text
Phone
  ↕
Local data
  ↕
Encrypted sync
  ↕
PC
```

Do not solve synchronization first.

Possible implementation stages:

```text
V1
Phone only

V2
Desktop support using the same data model

V3
Manual import/export

V4
Automatic encrypted synchronization
```

The difficult distributed-sync problem should not block validating the core product.

---

## 21. Design constraints

Noeting should deliberately avoid:

- infinite feeds
- autoplay
- trending sections
- public popularity metrics
- streaks
- points
- follower counts
- engagement notifications
- algorithmically chosen next-content
- excessive gamification
- forced daily usage
- plugin sprawl
- organizational busywork
- automatic AI chatter

The app should be capable of saying:

**Enough for today.**

---

## 22. Core product principle

The app should not ask:

**What can we show you next?**

It should ask:

**Did this help you think, create, or return to what matters?**

The ideal flow is:

↓
